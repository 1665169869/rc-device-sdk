# 卡内字节格式

> 本文只记录**已实测确认**的格式事实。适用驱动：
> `LC32RFRW.dll`，SHA-256 `f2f483e08ba8048ffd1c57e66cb35d9e32c1c1e280dc5f2ff100a5d881bccbc0`。
> 换驱动必须重新评估全部结论。

## 有效数据

卡内只有 **8 字节**有效数据（页 1 + 页 2 各 4 字节），页 3–7 全 0。

```text
页1 = 5B EC | B2                                  | B3
             高4bit = room_index 低4位              room_index >> 4
             低4bit = lost_flag（不属于序号）
页2 = 时长码 | 卡号低 | 卡号高 | 年月
```

## room_index 位打包

`room_index` 是 **12 bit（0–4095）**，必须用位打包函数处理。

| 规则 | 说明 |
|---|---|
| 魔数 | `5B EC` 恒定，只做包识别，不参与序号运算 |
| `B2` | 高 4 bit = `room_index & 0x0F`；低 4 bit = 挂失标志（安装卡此位固定 `0x0C`） |
| `B3` | 完整 8 bit = `(room_index >> 4) & 0xFF` |
| 编码 | `B2 = ((idx & 0x0F) << 4) \| lost`、`B3 = (idx >> 4) & 0xFF` |
| 解码 | `idx = (B3 << 4) \| (B2 >> 4)`、`lost = B2 & 0x0F != 0` |
| 禁止 | 把 `B2 B3` 当 u16 大端/小端解析（`from_le_bytes` / `from_be_bytes` 都会错） |

实测对照（全部已进单元测试）：

| 房号 | room_index | B2 | B3 | 页1 |
|---|---|---|---|---|
| 220 | 15 | `F0` | `00` | `5BECF000` |
| 209 | 6 | `60` | `00` | `5BEC6000` |
| 260 | 39 | `70` | `02` | `5BEC7002` |
| 201 | 0 | `00` | `00` | `5BEC0000` |
| 205 | 3 | `30` | `00` | `5BEC3000` |
| 总控卡 | 4095 | `F0` | `FF` | `5BECF0FF` |

总控卡的 `B3 = 0xFF` 不是特例——它是 12 位全 1 的自然结果。

### 序号 4095 与总控卡字节冲突

序号 4095 的客卡页 1 = `5B EC F0 FF`，与总控卡完全相同，格式上无法区分；
解析按原 SDK 优先级判为**总控卡**。

因此**不要**把 `room_index = 4095` 分配给真实房间，否则该房间的客卡会被读成总控卡。
有效房间序号范围是 **0–4094**。

## 其余字段

| 项 | 规则 |
|---|---|
| 年月字节 | 高 4 位 = `(年−2000) & 0x0F`、低 4 位 = 月。**16 年一循环**。2026-11 = `0xAB`、2027-11 = `0xBB` |
| 时长·天 | `0x80 \| 天数`（1–63）；`>63` 走 `0xC0 \| round(天数/30)`，**30 天/月** |
| 时长·小时 | 客卡 `0x40 \| (小时+1)`；总控卡 `0x40 \| 小时`（差 1，实测） |
| 总控卡页 1 | `5B EC F0 FF` |
| 安装卡页 2 | 固定 `46 F2 00 01`，**不含**作业流水号 |
| 校时卡页 2 | 首字节 `0x06`（明文），编码 `YYMMDDHHmm` |
| 挂失 | 页 1[2] **低 4 位** = 1 |
| 作业流水号 | 16 位 = `日(5) << 11 \| 时(5) << 6 \| 小时内序号(6)`，序号 0–62 |
| 卡号字节序 | 低字节在前（页 2[1] = 低、页 2[2] = 高） |

**页 2[3] 与卡号必须来自同一个 `CardIssuedAt`**，否则会出现自相矛盾的卡。

## 原始直写（`write_raw`）

`write_raw` 把页 1 + 页 2 的 8 字节**原样**写进卡，不做任何位域检查、不计算时长码与卡号。

- 它**不是**一种卡型，没有编码规则，因此不进 46 项黄金向量；
- 唯一用途是逆向验证与现场排障（例如复现原厂某张卡的字节）；
- 写进去的字节若解析不出卡型，`parser` 返回 `CardKind::Unknown`——这是正常结果，
  不是解析失败；调用方必须把它当成「卡已写坏」处理；
- 擦卡不要用它：`erase_card` 有独立错误语义，且不消耗作业流水号。

## 驱动侧固定参数

- 写密码 `12000206`，十六进制 ASCII 传入；
- 必须 `config_parameter(0)`（明文）；加扰模式会「能读不能写」；
- 写卡：`te_setuppwm_asc(0,2,0,1,pwd)` → `te_writepwm_asc(0,1,pwd,页1)` →
  `te_writepwm_asc(0,2,pwd,页2)`；
- 写完立刻回读可能拿到**旧值**，回读校验要重试 3 次（间隔 200 ms）；
- `te_read_asc` 返回 29 字节（58 hex 字符），前 28 字节是卡数据，
  最后一字节是读卡器状态（恒 `0x02`）。
